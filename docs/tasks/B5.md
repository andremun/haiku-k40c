# Task B5: Minimum chain to one computation

Phase B: Nouveau dependency extraction. This file is the whole task text. `make check` verifies the
checks named here. General rules: `AGENTS.md`. Paths to Nouveau files in
any output are relative to `reference/nouveau/`; line numbers are 1-based.

- Why: the Haiku driver will not port all of Nouveau. This task says
  which parts the card needs before one compute job can run, in order,
  and which parts can stay out. Phase C and D take their work list from it.
- Inputs: the results of B1, B2, B3 and B6. Do not open
  `analysis/callgraph.json` or `registers/mmio_accesses.json` (the tool
  reads them). Read `analysis/compute_launch.md` and the first 60 lines
  of `analysis/callgraph.md`.
- Outputs: `tools/min_chain.py`, `analysis/min_chain.json`,
  `analysis/min_chain.md`.
- `min_chain.json` is one object with four lists:
  - `subsystems`: one entry for each member of `nvf1_chipset` in
    `nvkm/engine/device/base.c` (line 1770, 31 members):
    `{"name": "fb", "constructor": "gk110_fb_new", "file":
    "nvkm/engine/device/base.c", "line": 0, "status": "needed", "reason":
    "..."}`. `line` is the line of that member. `status` is `needed`,
    `optional` or `not-needed` for one compute job on a card that the
    video BIOS has started. `reason` has 5 words or more.
  - `steps`: the chain in the order in which it must happen, from "map
    the PCI memory regions" to "read the result buffer":
    `{"step": 1, "subsystem": "...", "what": "...", "functions": [...],
    "registers": [...], "firmware": [...], "status": "known", "notes":
    "..."}`. `subsystem` is a `subsystems` name, or `host` (PCI and
    memory mapping), `channel` (channel, address space and buffers of the
    job) or `mesa` (user-space half, from B6). A function is `{"name",
    "tree", "file", "line"}`; `tree` is `nouveau` or `mesa`, and the line
    holds the function name. `registers` is the list of `{"reg", "file",
    "line"}` that `registers/mmio_accesses.json` has for the Nouveau
    functions of the step, no more and no less: the tool copies them.
    `status` is `known`, `partly-known` or `unknown`: how well the
    analysis so far covers the step. 8 steps or more.
  - `gr_hooks`: one entry for each `.init...` and `.oneinit...` member of
    `gk110b_gr` in `nvkm/engine/gr/gk110b.c` (18 members): `{"hook":
    "init_zcull", "function": "gf117_gr_init_zcull", "file", "line",
    "use": "graphics-only", "reason": "..."}`. `file` and `line` are the
    definition of the function. `use` is `compute`, `graphics-only` or
    `both`.
  - `firmware`: `{"name", "source", "file", "note"}`. `source` is
    `built-in` (in the Nouveau source), `external-file` or `vbios`.
    The entries `fecs` and `gpccs` are required: find the two headers
    that `nvkm/engine/gr/gk110.c` includes for them.
- How to do it:
  - Write `work/B5/PLAN.md` (10 lines), then the tool. Work in this
    order and run `make check` after each part: `subsystems`, `gr_hooks`,
    `firmware`, `steps`.
  - Your decisions (status, reason, use, the functions of each step) are
    a table in `tools/min_chain.py` or in a file that it reads. The tool
    finds constructors, lines and registers itself: member lines with a
    regular expression, function lines from the `nodes` of
    `analysis/callgraph.json` (`name`, `file`, `line`), registers from
    `registers/mmio_accesses.json` (`function`, `file`, `line`, `reg`).
    For a function that is not a call graph node, use `grep -n` once and
    put the file in the table; the tool finds the line.
  - To read source, use `grep -n NAME file` and `sed -n 'A,Bp' file`
    for at most 60 lines at a time. `gf100_gr_init` is at
    `nvkm/engine/gr/gf100.c:2342` and calls the hooks in order.
  - The steps must contain `gf100_fb_init`, `gk104_fifo_init`,
    `gf100_gr_init`, `nve4_screen_compute_setup` and `nve4_launch_grid`,
    in this order. The Mesa file is
    `src/gallium/drivers/nouveau/nvc0/nve4_compute.c` (paths with `tree`
    `mesa` are relative to `reference/mesa/`).
  - Every subsystem with status `needed` is the `subsystem` of one step
    or more.
  - `tools/min_chain.py --check` writes nothing and exits 0 when the
    JSON file is what the tool generates. The same output on every run.
  - The work directory is `work/B5` (capital B).
- `min_chain.md`, 40 lines or more: the steps as a numbered list; which
  GR hooks are graphics-only and why; which firmware is needed and where
  it comes from; a list "Not known yet" with the steps that have status
  `partly-known` or `unknown` and what is missing for each (for example
  channel creation and the command buffer are not in the B2 call graph).
