# Macro task S1DMAMODEL: bounded host DMA mapping evidence model

## Why

S1DMACONTRACT identifies a conditional GPA/IOVA address chain. QEMU's RAM event
precedes ioctl success, and mapping removal changes coverage. Build the host
coverage/lifetime model required by a future D0 observer before any stage can run.

## Inputs

Read docs/STATUS.md, docs/DMA-CONTRACT.md (address chain, provider and D0 sections),
work/S1DMACONTRACT/RESULT.md and tools/dma_contract.py. Use its exact external
source pins for QEMU map/unmap and Linux Type1 semantics. Do not modify reference/.
Read existing memory address-domain types only as needed. No hardware research
outside the mapped-operation semantics is needed for this task.

## Outputs

- Plan the bounded interval/lifetime model before implementation. Keep launch,
  device, container, mapping generation, IOVA, HVA, extent and permissions distinct.
- Accept typed normalized syscall observations with explicit completion/results.
  Map announcements and incomplete calls never create successful coverage.
  Reject unsupported backend, overflow, holes, wrong permissions, stale epochs,
  incomplete observations and ambiguous map/unmap histories.
- Track complete successful mapping coverage and later removal conservatively.
  Define the evidence cutoff and invalidation rule. Handle failed maps and QEMU's
  source-backed EBUSY/unmap/retry sequence without an automatic stage retry.
  Do not mistake an ioctl's returned partial-unmap size for requested coverage.
- Do not invent a raw strace grammar. Keep a typed fixture boundary unless the
  exact observer format can be checked with a harmless owned-process fixture.
  No VFIO device, GPU, guest, root, process attachment or physical mapping call.
- Return host model diagnostics only. They must not set a production verified bit,
  install a provider, authenticate a host/guest handoff or enable publication.
- Test interval boundaries, split/partial removal, ordering, result failures,
  capacity exhaustion and independent generations. Add deterministic aggregate
  evidence if useful, generated by tools with exact --check support.
- Update design/evidence limits, status and work records. Run make check before
  committing working steps on main. No push.

## Limits

Host model/tests only. No VM, physical card, PCI/BAR, root, binding, reset, live
ioctl tracing or DMA experiment. D0 and D1 remain unimplemented and unauthorized.
A successful synthetic coverage test supplies no live IOVA or cache-visibility proof.
