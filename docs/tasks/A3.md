# Task A3: Inventory of the card's start-up script as it ran

Track A of `docs/S1-PLAN.md` (bring-up). This file is the whole task text.
`make check` verifies the checks named here. General rules: `AGENTS.md`.

- Why: when a guest starts, the card is not initialised. The Linux driver
  runs the start-up script stored in the card's firmware image before
  anything else works. A Haiku driver must do the same. This task makes the
  list of what the script did on this card, so that the executor can be
  designed for exactly those instructions, and so that the board operations
  (I2C, GPIO, VGA ports) can be checked for safety by the reviewer.
- Inputs (read these, not more):
  - The firmware image decoded by envytools `nvbios`:
    `~/haiku-cross/vbios/decoded/all.txt` (4,045 lines; the file is outside
    the repository, the image is NVIDIA's). Read parts with `sed -n`.
    The scripts begin at the line `Init script table at 0x4fcd: 7 main
    scripts` (line 771). An instruction line looks like
    `0x00008638: 7a 00 02 00 00 20 20 00 00          ZM_REG	R[0x000200] = 0x00002020`:
    the offset, the bytes (the first byte is the opcode), then the name
    and its arguments. Lines whose text part starts with `R[` (for example
    `		R[0x022588] = 0x00000000`) are data of the instruction before;
    they are not instructions.
  - The driver's log of a run with `debug=trace`:
    `reference/linux-run-debug/dmesg.txt.xz` (read with `xz -dc ... | sed -n`).
    A script line looks like
    `[   11.59] nouveau 0000:00:03.0: devinit: 0x00008637[0]: RESET_BEGUN`.
    The number in brackets is the nesting depth (`0` main script, `1` inside
    a call) while the instruction runs; a space `[ ]` means the instruction
    was skipped (a condition was false). A line whose text after `]: `
    starts with a tab is a detail line of the instruction before (for
    example a condition being tested), not an instruction.
- Definitions:
  - A log instruction: a `devinit: 0x........[c]: TEXT` line whose TEXT
    does not start with a tab. Its name is the first word of TEXT (split at
    a tab or a space). It is executed when `c` is not a space, skipped when
    it is a space.
  - A listing instruction: an instruction line of the decoded file (not a
    data line), after the line `Init script table at ...`.
  - A board operation: a log instruction named one of `ZM_I2C_BYTE`,
    `I2C_BYTE`, `ZM_I2C`, `I2C_IF`, `GPIO`, `GPIO_NE`, `IO`, `IO_MASK`,
    `IO_OR`, `IO_AND`, `ZM_CR`, `CR`, `TIME`, `CONDITION_TIME`, `INDEX_IO`,
    `ZM_INDEX_IO`. Its details are all log lines after it, up to (not
    including) the next log instruction line, each without the time stamp
    at the start (`[   11.59] `) and without white space at the end, empty
    lines left out. The details include lines of other subsystems (`i2c:`)
    and lines without any prefix.
- Output 1: `tools/devinit_inventory.py`. Standard library only. Options
  `--decoded F` (default `~/haiku-cross/vbios/decoded/all.txt`, expand
  `~`) and `--check` (write nothing, exit 0 when the two output files are
  what the tool writes, 1 when not). Same output on every run.
- Output 2: `analysis/devinit_inventory.json`, an object:
  - `"scripts"`: `[{"index": 0, "offset": "0x8637"}, ...]` from the lines
    `Init script N at 0x....:` (offset as in the file, lower case).
  - `"log_instructions"`, `"executed"`, `"skipped"`: counts.
  - `"opcodes"`: one object for each name in the log, sorted by name:
    `{"name": "NV_REG", "executed": N, "skipped": N}`.
  - `"static_instructions"`: the count of listing instructions.
  - `"log_offsets_not_in_listing"`: sorted list of the offsets of log
    instructions that are not the offset of any listing instruction, as
    `"0x%08x"`, each once.
  - `"listing_offsets_not_in_log"`: the count of listing instruction
    offsets that never appear in the log.
  - `"board_operations"`: in log order, `{"line": N, "offset": "0x%08x",
    "marker": "0" or "1" or " ", "name": ..., "text": TEXT without white
    space at its ends, "details": [...]}`. `line` is the 1-based line in
    the decompressed log.
- Output 3: `analysis/devinit_inventory.md`, generated by the tool:
  sections `## Summary` (the counts, the 7 scripts), `## Instructions`
  (a table of `opcodes`), `## Not in the listing` (the offsets of
  `log_offsets_not_in_listing`, then a sentence saying what they are:
  look at the log lines with these offsets and at the instruction before
  each of them), `## Board operations` (one table row for each, with line,
  marker, name, text, and the number of detail lines).
- How to do it:
  - `work/A3/PLAN.md` (10 lines). Write the tool in steps and run it after
    each: (1) the log, print the three counts; (2) the listing, print the
    script count and the instruction count; (3) the comparison and the
    board operations; (4) the files. Commit after each step and write two
    lines in `work/A3/NOTES.md` (done, next). If NOTES.md has steps, go on.
  - Take every number from the tool's output. Do not type counts.
  - Do not read `tools/check_repo.py` (AGENTS.md). Do not write the image
    or the decoded file into the repository.
  - The work directory is `work/A3`; the task ID in the task log is `A3`.
    `work/A3/RESULT.md`: the counts and the list of board operations by
    name, copied from the tool's output.
- Check: every key of the JSON file equals the reviewer's own count of the
  same files; the Markdown file has the sections and one row for each
  opcode and each board operation; `--check` passes twice.
