# Task B4: Linux dependency map

Phase B: Nouveau dependency extraction. This file is the whole task text. `make check` verifies the
checks named here. General rules: `AGENTS.md`. Paths to Nouveau files in
any output are relative to `reference/nouveau/`; line numbers are 1-based.

- Why: the Nouveau code for this card calls the Linux kernel for memory,
  locks, lists, timing, firmware files and DMA. The Haiku driver needs a
  Haiku replacement for each of these. This task lists every Linux
  symbol that the relevant files call and what replaces it.
- Inputs: `analysis/files.json` (B1; fields `path`, `class`), the files
  it names, `reference/haiku/headers`, `docs/design/design.md` lines 280
  to 345 (the four categories).
- Outputs: `tools/linux_deps.py`, `analysis/linux_deps.json`,
  `analysis/linux_deps.md`.
- Which symbols (the tool does this; the check uses the same rule and
  finds 139 symbols):
  1. Files: the entries of `analysis/files.json` with `class` not
     `other-chip` (70 files).
  2. Remove comments: replace each match of `/\*.*?\*/` (with
     `re.S`) by the same number of newlines, so line numbers stay right.
  3. A call is a match of `(?<![\w.>])([A-Za-z_]\w*)\s*\(`. The symbol is
     group 1; the line is the line of the match start.
  4. Drop these words: `if for while switch return sizeof defined do
     else case typeof __typeof__ offsetof`.
  5. Drop every name that Nouveau defines: in all `.c` and `.h` files
     under `reference/nouveau/` (use `os.walk(..., followlinks=True)`),
     the names matched by `^(\w+)\s*\(` and by `^#\s*define\s+(\w+)`,
     both with `re.M`.
- `linux_deps.json`: a list sorted by `symbol`, one entry for each symbol:
  `{"symbol": "kzalloc", "count": 39, "example": {"file": "...", "line":
  0}, "category": "C-replace", "haiku_api": ["calloc"], "header": null,
  "note": "..."}`.
  - `count`: the number of calls in the 70 files. `example`: one call.
  - `category`: `A-reimplement`, `B-extract`, `C-replace` or `D-ignore`
    as in the design document, or `X-not-linux` when the rule caught
    something that is not a Linux symbol (a local macro or a function
    pointer). Most Linux symbols are `C-replace`. `D-ignore` is for a
    symbol that serves only a part that the Haiku driver leaves out
    (AGP, for example).
  - `haiku_api` (required for `C-replace`, else `[]`): the Haiku kernel
    functions or macros that replace it. `header`: the file under
    `reference/haiku/` that declares all of them, for example
    `headers/private/kernel/lock.h`. Find it with `grep -rlw NAME
    reference/haiku/headers | head`. `header` is null only when every
    name is a standard C function (`malloc`, `calloc`, `free`, `memcpy`,
    `memset`, `memcmp`, `snprintf`).
  - `note`, 4 words or more: what differs. For example `kzalloc` returns
    zeroed memory, and `spin_lock_irqsave` also disables interrupts
    (Haiku: `disable_interrupts` then `acquire_spinlock`).
- How to do it:
  - Write `work/B4/PLAN.md` (10 lines), then the tool. Your decisions
    (category, haiku_api, header, note) are a table in the tool or in a
    file that it reads; the tool computes symbols, counts and examples.
  - First let the tool print the symbols with their counts and run
    `make check` to compare the number with the check. Then fill the
    table in groups: memory, locks, lists, atomic and reference counts,
    time, firmware, DMA and pages, bit and arithmetic macros, the rest.
  - Do not guess a Haiku name. If `grep` finds no Haiku function, use
    the nearest that exists and say so in `note`, or use category
    `A-reimplement` with the note "no Haiku equivalent, write it in the
    driver" (this is right for small macros such as `BIT`,
    `upper_32_bits` or `DIV_ROUND_UP`).
  - `tools/linux_deps.py --check` writes nothing and exits 0 when the
    JSON file is what the tool generates. The same output on every run.
  - The work directory is `work/B4` (capital B).
- `linux_deps.md`, 30 lines or more: one section for each group above
  with a table (symbol, count, Haiku replacement), and a section
  "Differences that matter" for replacements that do not behave the
  same (interrupt state, sleeping, zeroed memory, firmware loading).
- Check: the symbol list, counts and examples as the rule gives them;
  categories and headers as described. The check also knows that the
  memory, lock, list, sleep, firmware and DMA functions are `C-replace`
  and which Haiku functions replace `mutex_lock`, `spin_lock_irqsave`,
  `msleep` and `usleep_range`. The other decisions are yours and the
  reviewer reads them.
