# Macro task S1A4: Pre-start state and helper integration

## Why

The host ROM helpers and native allocation adapter now exist. Identify the
selected pre-POST lifecycle and prevent repeated startup during devfs reloads.
Do not assume normal-init functions run before POST.

## Inputs

Read docs/STATUS.md, ADRs 004-007, docs/S1-RECIPE.md, docs/DEVINIT-EXECUTOR.md,
work/S1BOARD/RESULT.md, and work/S1B2/FINDINGS.md.
Pinned Nouveau paths: engine/device/base.c:1770-1805,2889-2970;
core/subdev.c:81-118; subdev/devinit/{base,gf100,nv04,nv50}.c;
subdev/fb/{base,gf100,gk110}.c; subdev/i2c/{base,gk110,padgf119,busgf119,padg94,pad,bus,bit}.c;

## Outputs

- docs/S1-PRESTART.md: selected callbacks, lifecycle ordering, prerequisite resources,
  intended S1 omissions, evidence levels, and remaining hardware gates.
- A host-only one-shot startup controller with persistent caller-owned boot state.
- Source-backed host helper/transport implementation where its required inputs are established.
- Tests for duplicate/recreated startup, prerequisite failures, timeouts, transport failure,
  and refusal of hardware backends.
- Updated licensing, provenance, status, and work/S1A4/{PLAN,FINDINGS,RESULT}.md.

## Limits

No VM with a card, no PCI writes, no BAR access, no root, no binding, no manual reset.
A7 still needs the user's go-ahead. A source-backed candidate path is not hardware verification.
Preserve ROM policy and IOVA/publication proof requirements. Unknown prerequisites stop the model.
