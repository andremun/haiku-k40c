# Macro task S1B5: Haiku card launcher and identity reads

## Why

The user authorized Haiku read-only passthrough in ADR 005.
Build a bounded launcher and verify the development card identity under Haiku.

## Inputs

Read AGENTS.md, REVIEW.md, ADRs 004/005, docs/HAIKU_BUILD_TEST.md,
docs/S1-PLAN.md, tools/haiku/cardless_run.py, tools/haiku/app_vm.py,
tools/guest/linux-run.sh:19-23, src/os/HaikuProbe.c, and the build tools.
Use the pinned Haiku interfaces already recorded in docs/licensing.md.

## Outputs

- Update the repository rules and record ADR 005 before launcher implementation.
- Add tools/haiku/card_run.py with exact BDF, vfio-pci, sole-group, and VFIO access checks.
- Require the B5-tagged identity probe. Preserve memory-decode refusal and PMC_BOOT_0-only MMIO reads.
- Enforce one guest, an overlay, incremental logs, and a maximum 600-second deadline.
- Add host tests for refusal, stage validation, timeout, and result validation.
- Apply the four documentation fixes from the user's S1C/S1D review.
- Save dated cardless and B5 evidence in results, with command, driver hash, and logs.
- Re-pin shared Haiku tools in haiku-k40c-llm after committing tool changes.
- Update status and work/S1B5/PLAN.md, FINDINGS.md, RESULT.md.

## Limits

No root, host BAR access, binding change, manual reset, Linux --gpu, or vm-test.sh change.
Only 0000:04:00.0 may pass through. The VFIO startup reset is allowed.
Never touch 0000:03:00.0. No slow-window access or GPU write stage.
Ask before shutting down a running VM. Stop and report a hang or panic without a modified retry.
Do not start the board-operation policy macro task in this task.

## Check

Run make check before every commit and make vm-tools-test for shared tool changes.
Link both probes. Run the S1A cardless KVM check, then B5 identity reads.
A B5 pass proves only PMC_BOOT_0 under Haiku (HARDWARE_VERIFIED).
