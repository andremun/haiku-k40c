# Task D5: Launch descriptor and compute method encoding

Phase D: host-side algorithms and tests. This file is the whole task text. `make check` verifies the
checks named here. General rules: `AGENTS.md`. Paths to Nouveau files in
any output are relative to `reference/nouveau/`; line numbers are 1-based.

Plain C++17 built with `g++` on Ubuntu. `tests/Makefile` builds and runs
the tests. `make check` runs them.

- Why: a compute job is started by a 256-byte launch descriptor (Mesa
  calls it QMD) that says where the shader code is, how many threads
  run, how much memory they get and which constant buffers they see,
  and by two methods that give the GPU the address of the descriptor
  and tell it to launch. Milestone S3 needs exactly this. This task
  writes the descriptor builder and the launch methods, without hardware.
- Source to read (Mesa, directory
  `reference/mesa/src/gallium/drivers/nouveau/nvc0/`), with `sed -n
  'A,Bp'`:
  - `nve4_compute.c` lines 573 to 632 (`nve4_compute_setup_launch_desc`),
    535 to 547 (`nve4_cp_launch_desc_set_cb`) and 869 to 883 (the launch
    methods in `nve4_launch_grid`).
  - `cla0c0qmd.h`: do not read it whole. For one field: `grep -n
    'QMDV00_06_NAME' cla0c0qmd.h`. `MW(287:256)` means bits 256 to 287 of
    the descriptor, bit 0 being the lowest bit of word 0.
  - `analysis/compute_launch.md` (B6) lists the fields with their bits.
  - `nve4_compute.xml.h`: `grep -n 'LAUNCH' nve4_compute.xml.h` for the
    method numbers; `NV50_GRAPH_SERIALIZE` is in
    `../nv_object.xml.h`.
- Outputs: `src/compute/LaunchDesc.h`, `src/compute/LaunchDesc.cpp`,
  `tests/test_launchdesc.cpp`, one line in `tests/Makefile`,
  `docs/launch-descriptor.md`.
- The scaffold wrote the acceptance test `tests/accept/d5_accept.cpp`
  (101 checks). Read it first: it is the specification by example. Its
  expected descriptor words were computed from `cla0c0qmd.h`. When a
  descriptor differs, the test prints each differing word with its bit
  range: find the field with those bits and compare. You cannot edit
  the test.
- Interface, in namespace `k40::compute`:
  - Constants `kComputeClass` (`0xa1c0`), `kComputeSubchannel` (1, Mesa's
    `SUBC_CP`), `kQmdBytes` (256).
  - `class Qmd`: 64 words of 32 bits, all zero at the start.
    `set(unsigned hi, unsigned lo, uint64_t value)` stores a value in the
    bits `lo` to `hi` and leaves all other bits; a field may cross a
    word boundary. `uint64_t get(hi, lo) const`. `const
    std::array<uint32_t, 64>& words() const`. `std::invalid_argument`
    when `hi < lo`, `hi` is 2048 or more, the field is wider than 64
    bits, or the value does not fit in the field.
  - `struct ComputeJob { uint32_t codeOffset; uint32_t grid[3]; uint32_t
    block[3]; uint32_t sharedMemSize; uint32_t localMemLow; uint32_t
    numGprs; uint32_t numBarriers; };` with default values 0 and 1 for
    `grid` and `block`. `localMemLow` is `cp->hdr[1]` in Mesa.
  - `Qmd buildQmd(const ComputeJob&)`: every assignment of
    `nve4_compute_setup_launch_desc` up to and including
    `BARRIER_COUNT` (23 fields with `L1_CONFIGURATION`), not the
    constant buffers. A job value that does not fit its field gives
    `std::invalid_argument` (from `Qmd::set`).
  - `void setConstantBuffer(Qmd&, unsigned index, uint64_t address,
    uint32_t size)`: the four assignments of
    `nve4_cp_launch_desc_set_cb`. `std::invalid_argument`, with the
    descriptor unchanged, when `index` is above 7, the low 8 bits of
    `address` are not zero, the address needs more than 40 bits, or the
    size does not fit its field.
  - `std::vector<uint32_t> encodeLaunch(uint64_t descGpuAddr)`: the
    push-buffer words of `LAUNCH_DESC_ADDRESS` (the address shifted
    right by 8), `LAUNCH` (value 3) and `NV50_GRAPH_SERIALIZE` (value
    0), each as an increasing method with one data word on the compute
    subchannel. Use `k40::fifo::PushBuffer` from task D3
    (`src/fifo/PushBuffer.h`). `std::invalid_argument` when the low 8
    bits of the address are not zero or it needs more than 40 bits.
- How to do it:
  - Write `work/D5/PLAN.md` (10 lines). Then `Qmd` (run the acceptance
    test: `test_bitfield` must pass before you go on), then `buildQmd`
    as a table of `{hi, lo, name, source line}` and a loop, then
    `setConstantBuffer`, then `encodeLaunch`. Compile with `g++
    -std=c++17 -Wall -Wextra -Werror -Isrc tests/accept/d5_accept.cpp
    src/compute/*.cpp src/fifo/*.cpp -o build/d5 && build/d5`.
  - Every bit position and constant has a comment with its source line
    in `cla0c0qmd.h` or `nve4_compute.c`. Take the positions from the
    header, not from memory.
  - When a check fails, do not write a debug program. The test prints
    the word and the bit range.
  - `tests/test_launchdesc.cpp`: 15 checks or more of your own. Useful
    ones: `get` after `set` for a field that crosses two words,
    `buildQmd` with every job value at the largest value that fits, all
    eight constant buffers set, `encodeLaunch` decoded with
    `k40::fifo::decodeBuffer`. Do not assert behaviour that you did not
    derive from the source or from this text.
  - `tests/Makefile`: add `test_launchdesc:compute+fifo` and
    `d5_accept:compute+fifo` to `CXX_TESTS`. Change nothing else there.
  - `docs/launch-descriptor.md` (50 lines or more): a table of the
    fields (name, bits, value, source line), what Mesa leaves at zero,
    the launch methods, and "Not covered": the upload of the descriptor
    to GPU memory (`UPLOAD_*` methods), the setup methods of
    `nve4_screen_compute_setup`, the shader code itself, and anything
    else that S3 needs and this task does not provide.
  - Standard headers only. The work directory is `work/D5`.
- Check: the acceptance test file is unchanged, compiles without
