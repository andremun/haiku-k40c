# Task D4: Register-trace comparison tool

Phase D: host-side algorithms and tests. This file is the whole task text. `make check` verifies the
checks named here. General rules: `AGENTS.md`. Paths to Nouveau files in
any output are relative to `reference/nouveau/`; line numbers are 1-based.

- Why: when the Haiku driver runs on the card, the main way to find a
  mistake is to compare the register accesses it makes with those that
  Nouveau makes on the same card. Linux can record them (mmiotrace); the
  Haiku driver will record them in the text format of task D1. This
  task writes the tool that converts and compares the two.
- Outputs: `tools/compare_register_traces.py`,
  `tests/test_compare_traces.py`, `docs/register-traces.md`. Python 3,
  standard library only (`yaml` may be used for `--names`). No pytest.
- The scaffold wrote the acceptance test `tests/accept/d4_accept.py` (38
  checks). Read it first: it is the specification by example. You
  cannot edit it. Run it with `python3 tests/accept/d4_accept.py`.
- A trace in memory is a list of tuples `(op, offset, value)` with `op`
  `"R"` or `"W"` and two integers.
- Functions of the module:
  - `parse_trace(text)`: the text format of D1 (`R 0x000200
    0x00000100`; `#` starts a comment; empty lines are skipped). Any
    other line raises `ValueError`. `format_trace(trace)` writes it
    (offset 6 hex digits, value 8).
  - `convert_mmiotrace(text, bar0, size=0x1000000)`: Linux mmiotrace
    text. A line `R 4 TIME MAPID 0xADDRESS 0xVALUE 0xPC 0` is a read of
    4 bytes at a physical address; `W` is a write. Keep the lines with
    width 4 and `bar0 <= address < bar0 + size`; the offset is `address
    - bar0`. Skip all other lines (`VERSION`, `PCIDEV`, `MAP`, `UNMAP`,
    `MARK`, other widths, other address ranges).
  - `compare(expected, actual, writes_only=False,
    ignore_read_values=False, ignore=(), masks=None)` returns a dict
    `{"equal": bool, "matched": int, "mismatch": None or {...}}`. It
    walks both traces in order. `ignore` is a set of offsets that are
    dropped from both traces; `writes_only` drops all reads;
    `ignore_read_values` compares the offset of a read and not its
    value; `masks` maps an offset to the bits that are compared (default
    all bits). `matched` is the number of entries that agreed before
    the first difference. `mismatch` has `kind` (`"op"`, `"offset"`,
    `"value"`, `"missing"` when the actual trace ends first, `"extra"`
    when the expected trace ends first), `expected_index` and
    `actual_index` (positions in the traces as they were given, before
    anything was dropped; `None` for the side that has ended) and
    `expected` and `actual` (the two entries, or `None`). Compare `op`
    first, then `offset`, then `value`.
- Command line:
  - `compare_register_traces.py EXPECTED ACTUAL [--writes-only]
    [--ignore-read-values] [--ignore 0x000100,0x000140] [--mask
    0x000200=0xfffffff0 ...] [--names hardware/registers]`. Exit code 0
    and a line with the word "match" when the traces agree. Exit code 1
    on a difference, with a report: the kind, the number of matching
    entries, up to three expected entries before the difference, then
    the expected and the actual entry as `W 0x002140 0x7fffffff`. With
    `--names DIR` each entry also shows the register name from the YAML
    files of C1 (entries whose `reg` equals their `address`). Exit code
    2 for a file that cannot be read, a wrong number of arguments or a
    bad option value.
  - `compare_register_traces.py --convert-mmiotrace FILE --bar0
    0xf6000000 --output OUT` writes the converted trace.
