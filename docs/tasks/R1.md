# Task R1: Fix the defects that the external review found in the host code

Phase D (rework after the gate). This file is the whole task text. `make
check` verifies the checks named here. General rules: `AGENTS.md`.

- Why: an external review of 2026-10-13 ran the phase D code with inputs
  that our tests did not try and found seven defects. The driver will use
  this code on the real card, where a wrong page table or a corrupt command
  stream is a hardware fault, not a failed test. The defects are listed in
  `docs/external/2026-10-13-review-outcome-package-b.md`, section
  "Confirmed software findings", F1 to F7. Read that section only.
- The scaffold's tests are written: `tests/accept/r1_accept.cpp` (F1, F2,
  F3, F5, F6, F7) and `tests/accept/r1_accept.py` (F4). Both are in
  `tests/Makefile`, which now also builds every test with
  `-fsanitize=undefined`, so a shift by 64 stops the test with a "runtime
  error" line. Today `make -s -C tests` fails: 17 checks fail and three
  shifts by 64 are reported. When the task is done, all tests pass. Do not
  change the test files or the Makefile lines of R1 (`make check` compares
  them with recorded hashes).
- Read the test that belongs to the part you work on. Each CHECK says what
  must happen. Run one test program at a time:
  `make -s -C tests ../build/tests/r1_accept && build/tests/r1_accept`.
- What to change (the files and the rules; the details are in the tests):
  1. `src/mmu/PageTable.cpp`, F1 to F3. Check the page shift first (only
     12 and 17), before any `1ULL << pageShift`. Check that `va + size` and
     `phys + size` do not wrap around 2^64 (compare with subtraction:
     `size > UINT64_MAX - va`). Check that the physical range fits 40 bits.
     A new mapping must not overlap any mapped address of the other page
     size anywhere in its range, not only at the start of each page. An
     unmap with a page size that does not match the mapping must throw
     `std::invalid_argument` and change nothing. Every check runs before
     any change: a call that throws leaves the address space as it was.
  2. `src/compute/LaunchDesc.cpp`, F5. In `fld_shared_mem`, compute in 64
     bits before adding `0xFF`. `localMemLow` that does not fit its 24-bit
     field throws (do not mask it silently). `Qmd::get` refuses a field
     wider than 64 bits, as `Qmd::set` does.
  3. `src/fifo/PushBuffer.cpp` and `.h`, F6. `bindObject` throws
     `std::logic_error` when a packet still waits for data, as the other
     `begin...` functions do. Add `std::vector<uint32_t> finishedWords()
     const`: the same as `words()`, but it throws `std::logic_error` when
     `pending() > 0`. Do not change `words()`.
  4. `src/hw/RegisterIO.cpp`, F7. `parseTrace` refuses (with
     `std::invalid_argument`) a number that does not fit 32 bits, a token
     with characters after the number (`0x10zz`), a negative number, and a
     line with more tokens after the value, unless the next token starts
     with `#` (a comment). Parse with `std::stoull` and the `pos` argument,
     then check the range and that `pos` is the end of the token.
  5. `tools/qmd_compare.py`, F4. Options: `--reference F`, `--words F` (a
     text file with 64 hex words; without it, run `build/tests/ref_qmd
     --words` as now), `--header F`, `--out-json F`, `--out-md F` (the
     defaults are the paths used now), and `--verify`. Without `--verify`
     it writes the two files, but exits 1 and writes nothing when an input
     is invalid: an unknown field name, an unknown named value (no
     `#define` for it), a field listed twice, not exactly 64 words, or a
     word that is not hex of 32 bits or less. With `--verify` it writes
     nothing and exits 0 only when the inputs are valid, every field is
     equal, and both output files are exactly what it would write.
     `--check` stays and means `--verify` with the default paths.
     Replace `eval()` with a small function that computes the bit
     expressions of the header (numbers, `+`, `*`, parentheses); no `eval`.
- Keep the old behaviour where the tests do not ask for a change. All
  other tests must still pass: `d1_accept` to `d5_accept`, the four
  `test_*` programs, `ref_qmd`, the two Python tests, and the D6 checks of
  `make check` (`analysis/qmd_compare.json` must still be what the tool
  writes with the default paths).
