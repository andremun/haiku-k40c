# Task D6: The launch descriptor against the reference run

Phase D: host-side algorithms and tests. This file is the whole task text. `make check` verifies the
checks named here. General rules: `AGENTS.md`.

- Why: `src/compute/LaunchDesc.cpp` (task D5) builds the launch
  descriptor (QMD, 64 words) from the Mesa source. The reference run of
  2026-10-13 printed the descriptor that Mesa really sent to the card:
  155 fields, in `analysis/linux_run_shader.json` under `"qmd"` (task
  C5a). This task builds the descriptor of the same job with our code
  and compares every field. It is the first check of driver code
  against the real card.
- Inputs (read these, not more): `src/compute/LaunchDesc.h`;
  `reference/mesa/src/gallium/drivers/nouveau/nvc0/cla0c0qmd.h` (the
  field positions; 240 lines, read lines 1 to 60 and then use `grep`);
  `tests/Makefile`; `firmware/compute_add1.md` section "Launch
  descriptor" (the 30 fields that are not zero). Do not open
  `analysis/linux_run_shader.json` with the read tool (it is long): the
  tool of this task reads it.
- The job of the reference run, as a `ComputeJob`: `codeOffset =
  0x7f100`, `grid = {16, 1, 1}`, `block = {64, 1, 1}`,
  `sharedMemSize = 0`, `localMemLow = 0`, `numGprs = 5`,
  `numBarriers = 0`; then `setConstantBuffer(q, 7, 0x510000, 0x800)`.
- Format of the header: `#define NVA0C0_QMDV00_06_NAME MW(HI:LO)` gives
  the bits of a field. Bit B of the descriptor is bit `B % 32` of word
  `B / 32`. A field with an index is `NAME(i)` with
  `MW((640+(i)*1):(640+(i)*1))`: replace `(i)` by the index and
  compute. `#define NVA0C0_QMDV00_06_NAME_WORD 0x...` gives the number
  of a named value (`SAMPLER_INDEX_INDEPENDENTLY` is 0).
- Format of the reference: each entry is `{"name": ..., "value": ...}`.
  The name can end in an index, `CONSTANT_BUFFER_VALID(7)`. The value
  is a hex number (`0x7f100`), `TRUE` (1), `FALSE` (0), or a word: then
  the number is the define `NAME_WORD` of the header (name without the
  index).
- Outputs:
  - `tests/ref_qmd.cpp`: builds the descriptor of the job above. With
    the argument `--words` it prints the 64 words, one on a line, 8 hex
    digits, and nothing else. Without an argument it checks that
    `words()[8] == 0x7f100` and prints `ref_qmd: 1 checks, 0 failures`
    (exit 0), like the other tests. Add `ref_qmd:compute+fifo` to
    `CXX_TESTS` in `tests/Makefile`. The program is then
    `build/tests/ref_qmd`.
  - `tools/qmd_compare.py`. Standard library only. It runs
    `make -s -C tests` if `build/tests/ref_qmd` does not exist, runs
    `build/tests/ref_qmd --words`, reads the header and the reference,
    and writes the two files below. `--check` writes nothing and exits
    0 when the two files are what the tool generates, 1 when not.
  - `analysis/qmd_compare.json`: `{"words": ["0x........", 64 of
    them], "fields": [...], "equal": N, "different": N}`. `fields` has
    one object for each entry of the reference, in the same order:
    `{"name": "PROGRAM_OFFSET", "hi": 287, "lo": 256, "reference":
    "0x7f100", "reference_value": 520448, "ours": 520448, "equal":
    true}`. `reference` is the text of the reference,
    `reference_value` its number, `ours` the number in bits HI..LO of
    our words.
  - `analysis/qmd_compare.md`: sections `## Result` (the two counts,
    one sentence), `## Fields that are not zero` (a table: field, bits,
    reference, ours, equal; only fields where the reference value or
    ours is not 0), `## Differences` (a table of the fields with
    `equal` false, or the sentence `None.`).
- How to do it:
  - `work/D6/PLAN.md` (10 lines). First `tests/ref_qmd.cpp` and the
    Makefile line; run `make -s -C tests`; commit. Then the tool in
    steps (header, reference, compare, files); commit. Then
    `make check`.
  - If a field is different, do not change `src/compute/`: report it.
    A difference is a finding, and the reviewer decides what to do.
  - `work/D6/RESULT.md`: the two counts and the list of differences,
    taken from the JSON file with a command.
  - Do not read `tools/check_repo.py` (AGENTS.md). The work directory
    is `work/D6`; the task ID in the task log is `D6`.
- Check: the words are those of the D5 code for this job; every row of
  `fields` is what the reviewer's program computes (name, bits, both
  values); the document has the sections and the rows; `--check`
  passes twice; all tests pass.
