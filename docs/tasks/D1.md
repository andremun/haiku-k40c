# Task D1: Register access abstraction

Phase D: host-side algorithms and tests. This file is the whole task text. `make check` verifies the
checks named here. General rules: `AGENTS.md`. Paths to Nouveau files in
any output are relative to `reference/nouveau/`; line numbers are 1-based.

Plain C++17 built with `g++` on Ubuntu. `tests/Makefile` builds and runs
the tests. `make check` runs them.

- Why: every later piece of driver logic (page tables, FIFO, GR start)
  talks to the card through one small interface. With a mock behind the
  interface the logic runs on Ubuntu without a GPU; with a recorded
  trace behind it, the logic is compared with what Nouveau did. This
  task writes the interface, the mock and the trace replay.
- Outputs: `src/hw/RegisterIO.h`, `src/hw/RegisterIO.cpp`,
  `tests/test_registerio.cpp`, `tests/Makefile`, `docs/register-io.md`.
- The scaffold wrote the acceptance test `tests/accept/d1_accept.cpp`
  (57 checks). Read it first: it is the specification by example. You
  cannot edit it, and `make check` compiles it with
  `g++ -std=c++17 -Wall -Wextra -Werror -Isrc tests/accept/d1_accept.cpp
  src/hw/*.cpp` and runs it.
- Interface, all in namespace `k40`, declared in `src/hw/RegisterIO.h`:
  - `struct Access { enum Op { READ, WRITE }; Op op; uint32_t offset;
    uint32_t value; };` One register access. For a read, `value` is the
    value that was returned.
  - `class RegisterIO`: virtual destructor, pure virtual
    `uint32_t read32(uint32_t offset)` and
    `void write32(uint32_t offset, uint32_t value)`, and a non-virtual
    `uint32_t mask32(uint32_t offset, uint32_t mask, uint32_t value)`
    that does what Nouveau's `nvkm_mask` does: read the register, write
    `(old & ~mask) | value`, return the old value.
  - `class MockMMIO : public RegisterIO`: a register space in memory.
    `explicit MockMMIO(uint32_t size)` (bytes, all zero). An offset that
    is not a multiple of 4 or not below `size` throws
    `std::out_of_range`. `poke(offset, value)` and `peek(offset)` change
    and read a register without a log entry. `log()` returns the
    `std::vector<Access>` of all `read32` and `write32` calls;
    `clearLog()`. `onRead(offset, std::function<uint32_t(uint32_t
    current)>)`: the function gives the value that this read returns
    (the stored value does not change). `onWrite(offset,
    std::function<void(MockMMIO&, uint32_t value)>)`: called after the
    value is stored. The hooks model status registers and side effects.
  - `class TraceMMIO : public RegisterIO`: replays a recorded sequence.
    `explicit TraceMMIO(std::vector<Access> expected)`. `read32` returns
    the recorded value when the next expected access is a read of this
    offset. `write32` passes when the next expected access is a write
    of this offset and value. Anything else, also an access after the
    end, throws `TraceMismatch` and does not advance. `done()`,
    `position()`.
  - `class TraceMismatch : public std::runtime_error` with
    `size_t index() const` (the position of the expected access). The
    message contains the offset of the attempted access as `0x%06x`.
  - `std::vector<Access> parseTrace(std::istream&)` and
    `std::string formatTrace(const std::vector<Access>&)`. One access
    for each line: `R 0x000200 0x00000100` or `W 0x000200 0x00000100`
    (offset 6 hex digits, value 8). `#` starts a comment; empty lines
    are skipped; any other line throws `std::invalid_argument`.
- How to do it:
  - Write `work/D1/PLAN.md` (10 lines). Then the header, then the

    the first compiler error or `FAIL` line says what is missing.
  - `tests/test_registerio.cpp`: your own tests, in the same style as
    the acceptance test (a `CHECK(...)` macro, exit code 1 on failure),
    15 checks or more that the acceptance test does not have. Useful

    with only comments, hex values in upper case, a size that is not a
    multiple of 4.
  - `tests/Makefile`: the default target builds both test programs into
    `build/tests/` (from the repository root: `../build/tests/`) with
    `-std=c++17 -Wall -Wextra -Werror -I../src` and runs them. `make -s
    -C tests` exits 0 only when both pass.
