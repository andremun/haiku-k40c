# Task C2: Firmware

Phase C: hardware database and firmware. This file is the whole task text. `make check` verifies the
checks named here. General rules: `AGENTS.md`. Paths to Nouveau files in
any output are relative to `reference/nouveau/`; line numbers are 1-based.

- Why: the GR engine does not work until two small programs run on its
  controllers: FECS (the hub) and GPCCS (one for each GPC). The Haiku
  driver must load the same code. This task records exactly which code,
  where it comes from, under which license, and how Nouveau loads it.
- Inputs: `nvkm/engine/gr/gk110.c` lines 314 to 336,
  `nvkm/engine/gr/fuc/hubgk110.fuc3.h` and `gpcgk110.fuc3.h` (do not
  read them whole: the tool reads them; look at the first 10 lines),
  `nvkm/engine/gr/fuc/hubgk110.fuc3` and `gpcgk110.fuc3` (40 lines
  each), and in `nvkm/engine/gr/gf100.c` the functions
  `gf100_gr_init_ctxctl_int` (line 1831), `gf100_gr_load_fw`,
  `gf100_gr_load` and `gf100_gr_nofw` (lines 2560 to 2612).
  `docs/licensing.md` for the license rules.
- Outputs: `tools/fw_manifest.py`, `firmware/manifest.yaml`,
  `firmware/README.md`. No binary file in the repository.
- `manifest.yaml` is a mapping with three lists. The tool computes all
  of it except the `what` texts.
  - `built_in`: one entry for each array `static uint32_t NAME[] = {`
    in the two headers (4 arrays):

    ```yaml
    - name: gk110_grhub_code
      engine: fecs                 # hub header: fecs; gpc header: gpccs
      kind: code                   # the last part of the name: code or data
      source: built-in
      file: nvkm/engine/gr/fuc/hubgk110.fuc3.h
      first_line: 209              # the line with the array name
      last_line: 1046              # the line with };
      words: 0                     # number of 0x........ values
      size_bytes: 0                # 4 * words
      sha256: '...'                # of the words packed as little-endian
                                   # 32-bit: struct.pack('<%dI' % n, *words)
      asm_source: nvkm/engine/gr/fuc/hubgk110.fuc3
      asm_includes: [com.fuc, hub.fuc, macros.fuc]   # sorted, no duplicates
      license: MIT                 # from the SPDX line, line 1 of the header
    ```

    A value is 8 hex digits after `0x`. Drop comments (`/* ... */`)
    before you look for values: a comment such as `/* 0x0058: ... */`
    is not a value.
  - `external`: one entry for each `gf100_gr_load_fw(gr, "NAME",
    &gr->ENGINE.FIELD)` line in `gf100_gr_load`:
    `{filename: fuc409c, engine: fecs, kind: code, source:
    external-file, requested_at: 'nvkm/engine/gr/gf100.c:2602',
    distribution: do-not-distribute, needed: false}`. `kind` is `code`
    when FIELD is `inst`, else `data`.
  - `load_sequence`: one entry for each call in the body of
    `gf100_gr_init_ctxctl_int`, in order: `{line: 1841, call:
    nvkm_mc_unk260, what: "..."}`. A call is a match of
    `\b(nvkm_\w+|gf100_gr_\w+)\(` on a line of the body (from the line
    after `gf100_gr_init_ctxctl_int(` to the first line that starts with
    `}`). There are 17. `what` has 4 words or more and says what the
    call does to the hardware; read the function before you write it.
- How to do it:
  - Write `work/C2/PLAN.md` (10 lines), then the tool, then the README.
  - The `what` texts are a table in the tool (line number to text).
  - `tools/fw_manifest.py --check` writes nothing and exits 0 when the
    manifest is what the tool generates. The same output on every run.
    Write the file with `yaml.safe_dump(data, f, sort_keys=False)`.
  - `tools/fw_manifest.py --extract DIR` writes the four arrays as
    `DIR/NAME.bin` (the packed words). Use `build/firmware` to try it;
    `build/` is ignored by git. Do not put a `.bin` file in `firmware/`.
  - The work directory is `work/C2` (capital C).
- `README.md`, 50 lines or more, with these sections:
  - "Which code": the four arrays, sizes, who wrote them (the copyright
    notice of the `.fuc3` files) and the license. Say clearly whether
    this is NVIDIA's firmware or Nouveau's own code.
  - "How Nouveau chooses": the list `gk110b_gr_fwif` in
    `nvkm/engine/gr/gk110b.c`, the role of `gf100_gr_load`, the
    `NvGrUseFW` option and `gf100_gr_nofw`. Which path is the default?
  - "How it is loaded": the load sequence in words, with `file:line`
    references.
  - "What the Haiku driver must do": the list of steps it has to
    reproduce, and what it may distribute.
  - "Not known": what this task could not establish (for example what
    `nvkm_mc_unk260` does, or what the code does after it starts).
- Check: every value of `built_in`, `external` and the (line, call)
  pairs of `load_sequence` against the source; the README sections named
  by their key words (`NvGrUseFW`, `gf100_gr_load`, `gf100_gr_nofw`,
  `gf100_gr_init_ctxctl_int`, `MIT`, `Not known`); every `nvkm/...:N`
  reference in the README is a real line; `--check`.
