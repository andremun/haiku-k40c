## Key findings

1. `gk104_chan_ramfc_write` (the most important function) writes 13 values into the instance block: USERD base address (0x08, 0x0c), magic 0x0000face (0x10), 0xfffff902 (0x30), command-buffer offset (0x48, 0x4c), 0x20400000 (0x84), devm mask (0x94), 0x00000100 (0x9c), 0x0000001f (0xac), privilege flag (0xe4), channel ID (0xe8), 0xf8000000 (0xb8), 0x10003080 (0xf8), 0x10000010 (0xfc), then calls nvkm_done. All 13 writes use `nvkm_wo32` (not tracked in MMIO access db because it's a write-through-mapping call, not wr32).

2. `gk110_chan_preempt` is a two-tier function: if the compute group has its own hw preempt, delegate to it; otherwise fall back to `gf100_chan_preempt` which writes the channel ID to register 0x002634.

3. `gk104_chan_bind` calls `gk104_chan_bind_inst` internally (not a separate top-level member). bind_inst writes `0x80000000 | chan->inst->addr >> 12` to the instance-block register.

4. USERD clear (`gf100_chan_userd_clear`) clears 10 shadow-register locations (0x040, 0x044, 0x048, 0x04c, 0x050, 0x058, 0x05c, 0x060, 0x088, 0x08c).

5. All 8 top-level members are needed for compute. The 9 data/value members are also needed (instance size, zero-fill, VMM, USERD bar/size, RAMFC devm/priv are all required channel configuration).

6. `depends_on` is empty: no functions call other subsystem functions directly. All operations are MMIO/register-level via the device handle.
